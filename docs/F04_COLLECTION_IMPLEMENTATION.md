## Proposed routes and ownership

F04-02 implements `/collection` for provider/broadcast selection and Start, and `/collection/:roundId` for a durable existing round. F04-03 adds `/collection/:roundId/suggestions` for review and acceptance. These are planned routes, not currently registered. `/integrations` remains the actual account/permission destination; future dashboard/history/OBS/payment pages are not linked as working screens before their owners implement them.

Routes compose the creator-session boundary, workspace layout and independent collection/review features. Features do not import sibling session or business features. `services/collection` will own validated HTTP operations; the existing narrow contracts facade exposes only the reviewed schemas when a concrete caller is added. Query keys include authority generation, round/provider/connection and pagination parameters. Local React state holds form drafts and dialog choices; the URL holds non-secret resource IDs and review navigation. No additional global store or form library is justified here.

Do not duplicate server state in loaders plus Query caches. All private reads wait for authenticated authority; current terms/restrictions remain server-checked. Session rotation clears drafts and stops polling/queries. Provider and viewer text stays text. Overlay/guest/staff grants never enter creator clients or caches.
