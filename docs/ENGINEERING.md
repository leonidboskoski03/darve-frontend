# Engineering standards

These standards apply from the first component. [ARCHITECTURE](ARCHITECTURE.md) defines ownership; [PLAN](PLAN.md) defines batch acceptance. Prefer explicit small implementations to generic frameworks created before use.

| Area                  | Rule and review evidence                                                                                                                                                                                                                                                                                                                                 |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Engineering standards | Strict TypeScript, named domain concepts, semantic HTML, explicit async/loading/error states and narrow module APIs. Do not use `any`, unsafe casts, non-null assertions or broad suppression to avoid understanding a contract. Explain intentional exceptions in reviewed code/design changes.                                                         |
| Architecture          | Enforced dependency direction, slice isolation and named public entries. Keep route composition, domain UI and infrastructure separate. No universal utility or service dumping ground.                                                                                                                                                                  |
| Design system         | Semantic color/type/space/radius/focus tokens and accessible stateful primitives. Preserve selected references; do not add arbitrary per-screen values when a token covers the need.                                                                                                                                                                     |
| Motion system         | Framer Motion for React presence/layout/interactions; GSAP for coordinated sequences. Narrow adapters, reduced motion, cleanup and one property owner. No business state transitions in animation callbacks.                                                                                                                                             |
| Routing               | Lazy screen modules; explicit layouts and not-found/error boundaries; title/focus handling. Reviewed URL parsing and safe internal return paths. No fabricated protected routes before session mapping.                                                                                                                                                  |
| Authentication        | Backend cookie sessions and documented CSRF. Creator/staff/guest/overlay scopes are separate. No tokens in frontend persistence; expiry/logout cancels requests, closes streams and clears private state.                                                                                                                                                |
| Authorization         | Render only server-permitted actions but enforce every action at the API. Hidden controls and frontend flags are never a permission boundary. Verify denied and cross-resource actions.                                                                                                                                                                  |
| API contracts         | Pin public contracts from an exact backend revision. Validate envelopes/status/content type with supplied adapters. No duplicated DTO definitions, raw database rows or browser provider credentials.                                                                                                                                                    |
| Server state          | Query keys include authority/resource/filter context; one cache owner. Configure retries and freshness per read; monetary/coin commands never retry automatically. No persisted private query cache.                                                                                                                                                     |
| Client state          | Local state/reducer for transients; URL for shareable filters. Add global state only for a documented cross-tree frontend need. Derive countdowns/totals from authoritative data.                                                                                                                                                                        |
| Forms                 | Start with semantic forms, controlled/uncontrolled fields as appropriate and Zod at boundaries. Accessible labels, help/error association, summary/focus on failure; preserve safe drafts. Disable duplicate submit while pending, retain idempotency semantics. Server remains authoritative. Add a form library only if proven complexity warrants it. |
| Realtime              | One owned subscription per resource/authority, cleanup on unmount/logout, version/freshness-aware snapshots. Resync refetches on the existing connection when contract requires it. Do not accumulate monetary deltas or reconnect forever to the same initial event.                                                                                    |
| Error handling        | Separate sign-in, denied, missing, stale/conflict, throttled, unavailable, protocol and offline states. Never convert errors into empty/success results. Show safe actionable copy and request IDs only when supplied. No raw server/provider messages or secrets.                                                                                       |
| Testing               | Test invariants and user behavior at the right layer. Unit for exact formatting/state transforms, component for interactions/errors, contract for adapters, browser for navigation/auth/payment/realtime. Real provider/OBS tests retain explicit configuration and approval scope.                                                                      |
| Environments          | Local-first, explicit browser-public allowlist, loopback dev server, documented selected backend. No wildcard credential forwarding, hardcoded production host or silent fallback between ordinary/staging databases.                                                                                                                                    |
| CI/CD                 | Use the tiered gates in GIT_AND_CI_SETUP: light dev checks (format/links for docs only), full frontend/release acceptance before main. Keep relevant local tests. CI must work without sibling checkouts or secrets once contracts are packaged. Record actual hosted evidence in the owning implementation record. No automatic deployment.             |
| Security              | Text rendering, safe redirects, server-side permissions/CSRF, no secret persistence/logging. Treat dependency scripts, CI and test artifacts as privileged. HTTPS/cookie/CSP policy needs actual environment verification.                                                                                                                               |
| Observability         | Plan safe error categories, action outcome, timing and request ID. No query strings, receipt/grant URLs, tokens, donor text or raw payloads. Add a reporter only with reviewed fields, retention and scrub tests. Do not invent a backend telemetry endpoint.                                                                                            |
| Feature flags         | Start fail-closed for held capabilities. Server availability determines eligibility. Frontend presentation flags can hide unfinished UI but cannot activate backend features, grant permissions or change commercial rules. No flag provider is required for F00.                                                                                        |
| Release process       | Review into dev, verified immutable candidate promoted to main at authorized release. Record source, build, contract revision, environment, migrations and rollback compatibility. Do not auto-rollback a backend database with a frontend release.                                                                                                      |
| Documentation         | Own decisions/evidence in the relevant implementation record, statuses in FRONTEND_TASK_TRACKER and batch acceptance in PLAN. State actual checks and pending acceptance. Document setup and restart state so another engineer can continue without conversation memory.                                                                                 |
| Team workflow         | Small branches/PRs with problem, result, checks and limitations. One owner per active file/checkout; coordinate dependencies instead of editing concurrently. Husky is convenience; mandatory CI cannot be bypassed by local hooks.                                                                                                                      |
| Infrastructure        | Vite on the host is sufficient now. Decide hosted static delivery, route fallback, origin/proxy boundaries and separate staff/OBS assets with real configuration later. No infrastructure provisioning or hosting provider switch in F00.                                                                                                                |

## Verification and hooks

Pre-commit uses lint-staged with ESLint and Prettier checks on staged files, not automatic global rewrites. Pre-push runs the full local `check`. Browser tests run against the settled production build in CI and locally for affected UI. Hooks must execute cross-platform using Node/npm and POSIX Git hooks; use `npm.cmd` for direct PowerShell commands.

Changes to core infrastructure require negative tests: forbidden imports, malformed contracts, authority expiry, cross-resource access, invalid config and unsafe error handling. F00 starts with architecture rejection cases, configuration checks, a safe route-error component case and desktop/mobile navigation/reduced-motion/accessibility browser cases. Axe checks supplement manual keyboard/screen-reader review; neither proves complete accessibility.

Accessibility target is WCAG 2.2 AA for completed screens, with manual focus, zoom, contrast, keyboard, touch and reduced-motion review. Initial automated checks cover available axe WCAG 2/2.1 A/AA rules; they are not a WCAG certification. Bundle sizes and performance budgets must be measured on real screens and devices, rather than invented from a starter shell.

Dependencies are exact-pinned with a lockfile. Evaluate peer/runtime compatibility and security notices before updates; never disable TLS or force incompatible dependency overrides to install. Keep a small dependency surface. New state/form/telemetry/flag frameworks need a concrete reason and a recorded decision.
