| Geometry          | 4px-based spacing, 6/10/14px radii, minimum 44px controls, bounded panel/dialog width and wrapping content. No decorative card shadows. Native modal top layer supplies stacking; skip link has its named layer.                                          |
| Motion            | Existing 120/220ms tokens retained. Border transitions and a pending indicator respect reduced motion; static skeletons avoid unnecessary motion. No new GSAP/Framer pattern is claimed here.                                                             |

The light canvas is tested because the selected standalone contribution design has a white form area. Its fixture toggle is local presentation state only. Component backgrounds use the scoped variables; callers must place the dialog within the intended scheme scope.

Loaded content replaces the entire loading region.                                                                                                                                                                                                                                                                                                                              |

Native `showModal` makes the background inert; initial focus goes to the safe close button. Escape/close request parent dismissal, native closure synchronizes state, and close/unmount clean up the modal. Native focus return is exercised. Backdrop click deliberately does not dismiss. Modal body scrolls within the viewport and background scrolling is locked. |

For example, a feature can compose `TextField` and `Button` inside `Dialog`, passing its own submit/pending/error behavior. Do not tie accepted terms, backend success, collection lifecycle or cancellation to modal visibility or animation completion. No authentication or financial action is demonstrated by this fixture.

## F01-03 motion patterns

Started 2026-10-27 on `feat/f01-03-motion-patterns` from clean, synchronized dev `5f4194bb4c610019da29f0303dfc2081e19c6a59`. Scope: concrete presentation adapters, reduced-motion/focus policy, lifecycle/interrupt testing and local preview evidence. No business API, provider, database, original-source, dependency or architecture-enforcement changes. Native dialog behavior is retained and reverified.

| Pattern                                                                                                    | Contract and ownership                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [MotionProvider](../src/motion/provider.tsx) and [preference hook](../src/motion/use-motion-preference.ts) | A useSyncExternalStore subscription responds to OS preference changes and removes its listener on unmount. Missing preference support defaults to still content. The installed Motion 14.6 hook was inspected and snapshots the initial value; the provider instead sets MotionConfig always/never from the live subscription.                                                                                                                                                                                                                                                                                                           |
| [Presence](../src/motion/presence.tsx)                                                                     | Display-only inline feedback. Entry is immediate and visible; normal exit fades for 120ms while immediately inert and aria-hidden. Reduced mode bypasses retention, including an exit already in flight. It exposes no animation-completion/business callback. Do not wrap inputs, interactive disclosures, dialogs or sensitive/authority-bound content that must disappear synchronously. Preference changes may remount its display-only subtree.                                                                                                                                                                                     |
| [LayoutList](../src/motion/layout-list.tsx)                                                                | Semantic named list with caller-owned stable, unique IDs/order/content. Only position transforms animate, for 220ms; no text scaling, drag controls, automatic sorting or business mutations. Stable IDs retain DOM and focus. Layout motion is disabled while focus is inside; features must move focus before removing a focused row. The [CSS accessibility guard](../src/motion/layout-list.css) forces final positions on focus/reduced-motion changes, including a projection already running. This is a final-pose override, not a second animation engine. A queued engine frame can finish without visually moving the content. |
| [SequenceReveal](../src/motion/sequence-reveal.tsx)                                                        | Existing 550ms, 12px landing entrance, limited to noninteractive marketing content. No opacity hiding. Scoped useGSAP/matchMedia setup reverts its tween/inline transform on interruption or unmount, including StrictMode. Missing matchMedia leaves still content. No new plugins/timelines, background loops or business callbacks.                                                                                                                                                                                                                                                                                                   |
| Native Dialog                                                                                              | Opening, inert background, focus, Escape and closing remain immediate. No animation delays the native lifecycle or return focus.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

Each adapter owns its engine/features. Presence uses domAnimation; LayoutList uses domMax. Features arrive with the adapter's lazy caller, synchronously available when that adapter renders. The global provider no longer launches a separate async feature runtime. The old Fade/runtime modules were removed; the foundation status text now renders directly instead of starting transparent while waiting for an engine. GSAP and Motion never animate the same property on one node. Existing CSS pending/focus behavior remains subject to the reduced-motion media query.

The isolated [motion fixture](../src/app/preview/motion-preview.tsx), within the existing component preview, composes real Button/Panel/ContentState primitives. Its toggles/reversal are explicitly local examples, not collection commands or backend state. The normal production router still has only its existing foundation/404 behavior; the fixture does not become a production route. Native dialogs, amounts, branding and feature layouts were not redesigned.
