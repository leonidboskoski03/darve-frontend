## Errors, replay and known gaps

[F06](F06_CONTRIBUTION_IMPLEMENTATION.md) maps the public challenge and private receipt read boundary. The pinned public/provider availability schema accepts only `available:false`, and ordinary Stripe/PayPal creation is intentionally disabled under backend B07-ACT-01. Public reads omit credentials, private receipt reads require the guest cookie, and provider return cannot confirm money. Payable checkout/capture requires reviewed exposure and a compatible authoritative availability projection; no cast, frontend flag or invented ready response can substitute for that prerequisite.

`ErrorResponseSchema` and `parseConsumerResponse` distinguish 401 sign_in, 403 denied, 404 not_found, 409 refetch, approved 429/503 retry and protocol_error. They neither fetch nor retry. Use safe code/request ID and applicable Retry-After, not raw message/stack/payload. Commands default to no automatic retry. Reconcile uncertain results through the correct private read before any deliberate repeat with the original key/terms.

The register assigns five gaps:

1. **GAP-202 — addressed in F02-02 client / affected features:** the pinned helper still accepts 200/201 and explicitly empty 204, but rejects 202. The JSON client now validates declared 202 with its exact schema and returns pending without status coercion or command retry. Each real feature must supply its mapped schema/status policy; package source remains unchanged.
2. **GAP-STAFF-ENVELOPE — resolved in F08-02/backend B13-05:** complete staff auth/session/acknowledgement/directory/audit/inspection/moderation responses now use exported schemas at the producer. Safe streamer dates and stored funding basis are explicit; staff start still differs from creator start. Actual SQL-backed response qualification passed.
3. **GAP-SUPPORT-SSE — resolved in F08-02/backend B13-05/B14:** creator/staff ticket/page/mutation and minimal live-event schemas are exported and enforced by HTTP producers. Strict creator schemas reject note/authority fields; real SQL-backed HTTP/SSE privacy proof passed. F08-04/05 supply separate creator/staff feature adapters.
4. **GAP-MODERATION-INPUT — resolved in F08-02/backend B13-05:** public RestrictionCommandSchema, ReviewFlagSchema, ReviewTransitionSchema and ReviewPageQuerySchema preserve domain constraints, revisions, reason and confirmation structure. Domain equality/permission/transition checks still authorize actual actions.
5. **GAP-OVERLAY-V2 — addressed in F02-03 frontend adapter / F07/F09/backend B15 consumer owner:** the pinned B11 reducer remains v1. The reviewed frontend adapter now delegates v1 and validates/reduces complete v2 frames without casts or dropped template fields, preserving 15-second freshness, monotonic time, resource/version floors and removal rules. Actual v1/v2 stream/reconnect/revocation proof passed. Renderer assets, selection UI and OBS acceptance remain F07/F09; no backend package change is claimed.

6. **F08-G01 — resolved in F08-02/backend B13-05:** admin 429 responses now validate as ErrorResponseSchema with matching request ID and bounded Retry-After metadata. Real shared Redis limiter/fail-closed tests and strict frontend parsing pass; automatic command replay remains disallowed.

Resolved contract gaps enable their feature work; they do not complete unsupported feature wiring. No real identity/provider/Resend delivery, sandbox payment, physical QR/OBS or deployment acceptance is established here.
